# Compound Engineering（复利式工程）全解析

> 原文来源：豆包，2026年4月27日

Compound Engineering（简称 CE，也叫 "复利式工程")是一套面向 AI 编程的 **循环式工作流框架**，核心是让每一次工程工作的产出，都能为后续工作提供可复用的知识资产，实现效率的 "复利增长"。它解决了传统 AI 开发框架（如 Superpowers）"用完即弃、知识无法沉淀" 的痛点。

---

## 一、核心原理：让 AI 开发 "越做越轻松"

传统 AI 开发框架（如 Superpowers）的流程是：`brainstorm→plan→execute→review`，它解决了 "从瞎聊到流程化用 AI" 的问题，但存在致命缺陷：**每次开发都是独立 session，经验、踩坑记录无法沉淀，下次从零开始**。

CE 的核心创新，是在流程中加入了 **Compound（沉淀）环节**，形成闭环：

```
Plan（规划）→ Work（执行）→ Review（审查）→ Compound（沉淀）→ Repeat（复用）
```

### 四个核心环节

| 环节 | 说明 |
|------|------|
| **Plan（规划）** | AI 深入理解需求与代码库，输出可执行的详细方案（含风险点、测试策略），避免盲目开发。 |
| **Work（执行）** | 在独立分支中增量开发，边写边验证（自动运行测试、检查代码规范），降低返工成本。 |
| **Review（审查）** | 多 Agent 交叉审查，避免开发者自审的盲区，同时记录问题与改进点。 |
| **Compound（沉淀）** | 把本次开发的经验、踩坑记录、解决方案，结构化存入知识库（`docs/solutions/`），形成可复用的资产。 |

---

## 二、与 Superpowers 的核心区别

| 对比维度 | Superpowers | Compound Engineering |
|----------|-------------|---------------------|
| **核心逻辑** | 单次流程的标准化 | 循环式流程 + 知识复利 |
| **知识沉淀** | 无，session 结束即丢弃 | 结构化存入知识库，永久复用 |
| **开发成本** | 边际成本不变，每次开发难度相同 | 边际成本递减，同类开发越做越快 |
| **适用场景** | 一次性任务、短期项目 | 长期维护项目、团队协作、需知识传承的场景 |

## 三、使用示例：给电商项目加优惠券系统

以 Claude Code 中使用 CE 插件为例，完整流程如下：

### 阶段 1：规划（`/ce:plan`）

- 输入需求："给电商项目添加优惠券系统，支持满减、折扣、叠加规则"
- AI 输出：数据库设计（优惠券表、用户关联表）、API 接口定义、前端交互方案、风险点（并发领取防超发、过期处理）

### 阶段 2：执行（`/ce:work`）

- 自动创建独立分支，按计划分步骤开发：先建表→写 API→前端集成
- 每一步自动运行单元测试

### 阶段 3：审查（`/ce:review`）

- 多 Agent 交叉检查：代码规范、逻辑漏洞、安全风险
- 比如发现 "并发领取未加锁" 的问题

### 阶段 4：沉淀（`/ce:compound`）

AI 自动生成结构化文档：

```
Problem    ：优惠券并发领取导致超发
What Didn't Work：无锁实现导致的竞态条件
Solution   ：使用分布式锁 + 数据库乐观锁
Prevention ：后续所有库存/券类操作必须加锁校验
```

文档存入 `docs/solutions/`，下次做类似功能时，AI 会自动复用这份经验。

## 四、适用场景

| 场景 | 说明 |
|------|------|
| **长期维护的项目** | 代码库持续演进、团队成员变动频繁，需要沉淀架构规则与踩坑经验。 |
| **团队协作开发** | 多人协作时，通过统一的沉淀流程，保证知识共享、减少重复踩坑。 |
| **质量优先的项目** | 如金融、医疗系统，技术债务成本高，需要强制沉淀问题与解决方案。 |
| **频繁迭代的产品** | 功能更新快、bug 修复频繁，需要让 AI 快速复用历史经验，提升迭代效率。 |

## 五、核心优势

| 优势 | 说明 |
|------|------|
| **效率复利** | 同类开发任务，随着知识库积累，开发时间可缩短 50% 以上。 |
| **知识资产化** | 把开发者的隐性经验，转化为可被 AI 复用的显性知识。 |
| **减少技术债务** | 每次开发都沉淀问题与预防方案，避免重复踩坑。 |
| **流程可落地** | 基于 Claude Code 插件，直接通过命令调用，无需复杂配置。 |

## 六、CE 与 Superpowers 的关系

### 两者是"升级替代"关系，而非"二选一"

Superpowers 的核心价值，是把"跟AI瞎聊"变成了 **单次任务的标准化流程**，解决了"怎么用AI写好单次代码"的问题。但它的致命问题是：**任务结束就清零，没有知识沉淀**。

CE 不是完全抛弃 Superpowers 的流程，而是 **在它的基础上，补了最关键的"闭环环节"**：

```
Plan → Work → Review → Compound（沉淀） → 复用
```

- 前三个步骤，其实就是 Superpowers 的核心逻辑
- 多出来的 `Compound` 环节，就是把本次的踩坑、方案、经验，结构化存入知识库，让后续任务直接复用。

### 切换建议

#### ✅ 强烈建议直接切换 CE 的场景

- 在做 **长期维护的项目**（比如公司业务代码、需要迭代半年以上的产品），而不是一次性小脚本。
- 经常遇到"上次踩过的坑，这次又忘了怎么解决"的情况，希望让AI帮你记住所有经验。
- 使用 Claude Code，CE 已经有成熟的插件/命令集，开箱即用。

#### ⚠️ 可以暂时保留 Superpowers 的场景

- 只是写 **一次性、短期的小脚本/小工具**，用完就扔，不需要沉淀经验。
- 还没摸透 CE 的流程，怕上手成本太高，想先用 Superpowers 维持稳定，慢慢过渡。

## 七、安装步骤

### 一、前置准备

- 已经安装并配置好 **Claude Code**（能正常在终端里用）
- 项目是 Git 管理的（必须，因为 CE 依赖分支管理）
- 终端能正常访问 GitHub（网络正常）

### 二、安装步骤（官方推荐版）

打开终端，进入项目根目录，按顺序执行：

#### 1. 添加 CE 插件源并安装

```bash
# 1. 在 Claude Code 里添加插件市场源
/plugin marketplace add EveryInc/compound-engineering-plugin

# 2. 安装 Compound Engineering 插件
/plugin install compound-engineering
```

#### 2. 项目初始化（关键！必须做）

在 Claude Code 会话里运行：

```bash
/ce:setup
```

这个命令会自动帮你做三件事：

- 在项目根目录生成配置文件 `compound-engineering.local.md`
- 创建知识库目录 `docs/solutions/`（后续所有沉淀内容都存在这里）
- 自动识别项目技术栈（比如 Python/JS/Java），配置适配的审查规则

### 三、快速验证安装是否成功

运行这个命令，看能不能正常输出帮助信息：

```bash
/ce:help
```

如果显示出 `/ce:plan /ce:work /ce:review /ce:compound` 等命令的说明，说明安装成功。

### 四、第一次使用（替代 Superpowers）

按顺序执行这 4 条命令，就能跑通完整的 CE 流程：

```bash
# 1. 规划：给需求做完整的方案（替代 brainstorm+plan）
/ce:plan "给用户模块添加手机号登录功能，包含验证码校验、防刷限制"

# 2. 执行：按规划开发，自动分支+增量编码（替代 execute）
/ce:work

# 3. 审查：多Agent交叉检查代码，发现问题（替代 review）
/ce:review

# 4. 沉淀：自动把本次的踩坑、方案、预防措施写入知识库
/ce:compound
```

### 五、避坑提醒

| 避坑项 | 说明 |
|--------|------|
| **别跳过 `/ce:setup`** | 不初始化目录，沉淀功能会失效。 |
| **必须在项目根目录操作** | 不然知识库和配置文件会生成在错误的位置。 |
| **不要手动修改 `docs/solutions/` 里的文件** | AI 会按固定格式写入，手动修改会导致后续无法复用。 |

### 六、卸载/重置（如果出问题）

```bash
# 卸载插件
/plugin uninstall compound-engineering

# 重置配置（如果想重新初始化）
rm -rf compound-engineering.local.md docs/solutions
```

## 九、总结

Compound Engineering 是 Superpowers 的 **升级版**，通过加入知识沉淀环节，解决了"用完即弃"的问题：

- **单次任务**：流程和 Superpowers 几乎一样，只是多了最后一步沉淀，不增加额外负担
- **长期收益**：同类开发任务越做越快，边际成本递减
- **团队价值**：把隐性经验转化为显性知识资产，支持团队协作和知识传承

**建议**：长期项目直接切换 CE，一次性任务可保留 Superpowers。
